# Comparison - Human and AI Versions (Stage 1 Lab, Part E)

- **Human version:** `source-code/smartcare_v01.py`, the handout's list, dictionary and function program.
- **AI version:** `source-code/smartcare_ai_version.py`, generated by ChatGPT from the Part D prompt.

## Comparison table

| Question | Human version | AI version |
| --- | --- | --- |
| Easy to understand? | Yes. Two short functions with clear names. | Yes. One short function with a docstring, but I had to check what `.strip()` does. |
| Runs successfully? | Yes. Prints the welcome line and both appointments. | Yes. Prints both appointments as dictionaries. |
| Uses only required features? | Yes. It stores the three values, plus a display function and a patient-name check. | Mostly. No database or GUI, but it adds `.strip()` and returns the appointment, which were not asked for. |
| Adds assumptions? | Assumes the time can be any text and that a patient is identified by name only. | Assumes every input is text and that no validation is needed. |
| Handles errors? | Partly. Rejects an empty or `None` patient name with a clear `ValueError`. Nothing else is checked. | No. A blank patient name is accepted, and `None` crashes with an `AttributeError`. |
| Could I explain it? | Yes. | Yes, after looking up `.strip()`. |

## Test results (Part F)

Both versions were run with the same five inputs. "Human, before" is the handout code as given. "Human, after" includes the Part G double-booking check.

| Test | Human, before | Human, after | AI version |
| --- | --- | --- | --- |
| 1. Normal appointment | Accepted | Accepted | Accepted |
| 2. Blank patient name | Rejected: `ValueError` | Rejected: `ValueError` | Accepted |
| 3. Same practitioner and time | Accepted | Rejected: `ValueError` | Accepted |
| 4. `patient_name=None` | Rejected: `ValueError` | Rejected: `ValueError` | Crashed: `AttributeError` |
| 5. `appointment_time=None` | Accepted | Accepted | Crashed: `AttributeError` |

## What the comparison shows

The AI version is shorter, but it does less checking than the handout version and fails in a less helpful way. Neither version stopped double bookings until the Part G improvement was added to the human version.
